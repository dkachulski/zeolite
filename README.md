# Trassing website

The trassing.com site, built with [Astro](https://astro.build) and
[Tailwind CSS](https://tailwindcss.com). It is a static site in two languages:

- `/` — English (default)
- `/bg/` — Bulgarian

## Working on it

```sh
npm install
npm run dev      # local dev server at http://localhost:4321
npm run build    # production build into dist/
npm run preview  # serve the production build
npm run check    # type-check
```

`dev` and `build` first run `npm run fonts` (see below). Other generators, to
run after changing their source:

```sh
npm run images   # AVIF copies of the CSS background images
npm run logo     # sizes of the SVG brand marks, after changing their wording
npm run icons    # favicons, home-screen icon and og-image.jpg, after changing
                 # the logo or the quarry photo
```

## Where things live

- `src/i18n/en.json`, `src/i18n/bg.json` — all page text. Both files must have
  the same keys; a missing key fails the build. Values may contain HTML
  (e.g. `SiO<sub>2</sub>`).
- `src/components/` — one component per page section; `Page.astro` puts them
  together and `src/pages/` has one route per language.
- `src/styles/global.css` — Tailwind setup, theme (Bootstrap's colours and
  breakpoints) and base styles. Tailwind's preflight is not used: the base
  layer reproduces the Bootstrap reboot the design was made with.
- `src/styles/bootstrap.css` — the few Bootstrap component styles the design
  uses (buttons, dropdowns, accordion, table).
- `src/styles/site.css` — the site's own styles.
- `src/scripts/site.ts` — all behaviour: dropdowns, collapses, mobile menu,
  map, product cards, counters, copy buttons, and what loads after the page:
  the remaining font weights, the background photos and the hero video.
- `src/assets/` — images. Background images used from `site.css` also have an
  AVIF copy; after adding or replacing one, run `npm run images`.
- `src/assets/fonts/`, `src/styles/fonts.css`, `src/styles/fonts-deferred.css`
  — generated by `scripts/subset-fonts.mjs`: Roboto cut down to the
  characters in `src/`, with regular and bold on the first paint and the
  other weights loaded after the page. Never edit them by hand.
- `src/components/BrandText.astro` — the "TRASSING.COM" logo and the footer's
  "@ trassing.com", drawn as SVG text so the brand colours don't fail the
  contrast audit (logos are exempt from WCAG contrast rules).
- `src/seo/structured-data.ts` — schema.org data for search engines
  (organisation, website, FAQ); `src/pages/sitemap.xml.ts` — the sitemap.
- `public/` — files served as-is: the hero video (AV1, with H.264 for
  browsers without AV1), favicons, `og-image.jpg`, `robots.txt`,
  `site.webmanifest` and `CNAME`.

## Branches and deploying

- `source` — this code. Work here (or in branches merged into it).
- `main` — the built site only, which GitHub Pages serves as plain files on
  trassing.com. It is generated; never edit it.

Every push to `source` runs `.github/workflows/deploy.yml`: it builds the site
and commits `dist/` to `main` (with `.nojekyll`, so Pages serves it as is),
and Pages publishes it within a minute or two. To redeploy without changes,
run the workflow from the Actions tab. To roll back, revert the bad commit on
`source`, or revert the last deploy commit on `main`.
